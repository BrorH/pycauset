## What it does
`PYBIND11_MODULE(_pycauset)` registers one translator (`dtype_error` -> `TypeError`,
`linalg_error` -> `numpy.linalg.LinAlgError`) and then binds five groups.
- Classes. One Python class per *structure*: `MatrixBase` -> `DenseMatrix`, `TriangularMatrix`,
  `DiagonalMatrix`, `IdentityMatrix`, `SymmetricMatrix`, `AntiSymmetricMatrix`,
  `HermitianMatrix`, `SkewHermitianMatrix`; `VectorBase` -> `DenseVector`, `UnitVector`. The dtype
  is an attribute. A `polymorphic_type_hook` maps every C++ object to its structure class
  (`bindings_common.hpp:126-140`). Every method is generic over dtype through `visit_matrix` /
  `visit_vector`.
- Operators. `+ - * /` for matrices go through one helper, `matrix_arith`: a scalar goes to
  `scalar_op`, a matrix / ndarray / vector to the element-wise entries. Anything else returns
  `NotImplemented`. `@` has four overloads (matrix, vector, ndarray, anything -> NotImplemented)
  plus `__rmatmul__` for ndarrays. Vectors use `vector_arith`. The bitwise operators take
  objects of their own kind only.
- Indexing (`matrix_indexing.hpp`). It parses `(row, col)` keys made of ints, slices, `...`, 1-D int
  or bool arrays and lists. Dense matrices: views for step-1 slices, copies otherwise. Other
  structures: element by element. Writes into a scale / conjugation view first fold the view into
  storage (F-045).
- NumPy. Export is `export_numpy`: one path for every class, dtype and view, always a fresh,
  C-contiguous, writable copy, under the size guard. Import goes through five per-dtype ladders
  (`pc.asarray`, `vector_from_numpy`, `matrix_from_numpy`, `elementwise_operand_matrix_from_numpy`).
  Python adds `__array__`, `__array_ufunc__ = None` and `__array_priority__ = 1e6`
  (`__init__.py:305-321`).
- Module functions. Linalg entries, reductions, persistence and debug helpers, sprinkling.

## Procedure compliance (Adding Operations / project rules)
- "One code path per operation":
  - Two `norm` registrations.
  - `MatrixBase.eig*` besides the module `eig*`.
  - `matmul` reached by four `__matmul__` overloads plus a method.
  - Two slice-assignment value converters.
  - Two element readers (matrix / vector) that disagree on integer factors (C-7).
- "One templated kernel per family, not per dtype": violated by the import layer (65
  `py::isinstance<py::array_t<T>>` branches, C-12).
- "No NumPy behind a PyCauset call": kept. NumPy runs only when the user calls a NumPy function
  on an exported copy. `np.dot(A, A)`, `np.linalg.inv(A)` and `np.trace(A)` silently export;
  `np.sum(A)` raises `TypeError` (`__array_ufunc__ = None`). This is the 3.8 C-19 policy question.
- "Views are values": documented on Matrix Guide (writes do not show through slices). Kept by
  the bindings [repro t1].

## Findings

**C-1 (S1 critical, crash) `np.asarray`, `np.array` and `pc.to_numpy` of a closed matrix or vector
segfault the interpreter.** [repro]
- Where: `bind_matrix.cpp:255-257`. The plain-dense path calls
  `src.shared_mapper()->get_data()` with no null check, and `close()` resets the mapper
  (`PersistentObject.cpp:42`). Vectors export through `as_row_matrix(v)` and hit the same line
  (`bind_vector.cpp:396`).
- Repro (`t5.py`, one process per case):
  ```
  A = pc.zeros((3, 3)); A.close()
  np.asarray(A), pc.to_numpy(A)          -> Segmentation fault (exit 139)
  v = pc.zeros(3); v.close(); np.asarray(v) -> Segmentation fault
  A + 1, A @ A, pc.sum(A), A[0, 0], A.T export -> RuntimeError: Backing file has been closed.
  A[0:2, 0:2]                            -> a DenseMatrix view over no storage (raises on use)
  ```
- Scenario: `close()` is the documented way to release a file early. Any later `print(np.array(M))`,
  a debugger's variable view or a plotting call kills the Python process and loses the session.
- Fix:
  - One `require_storage(obj)` check at the top of `export_numpy`.
  - The same check in the slice-view constructor (`slice_dense_matrix`), which today builds a
    view of a null mapper.
  - Better, one guard in `PersistentObject` (`data()` throws when `!mapper_`), so no path can
    dereference it.
  - Raise `ValueError("operation on a closed matrix")`, as Python file objects do (C-6).
- Regression test: every public method, operator and export on a closed matrix and vector raises
  `ValueError` (subprocess, so a crash fails the test rather than the run).
- **Fixed (session 9):** `require_mapper()` is public and every reader goes through it (the
  export, slices, the kernels that read `shared_mapper()->get_data()` directly); a closed object
  raises `ValueError("operation on a closed matrix or vector ...")`.
  `test_3_7_C1_closed_objects_raise_instead_of_crashing` (subprocess).

**C-2 (S1 critical, silent wrong values) A list key is read as `(row, col)`: `A[[0, 2]]` returns the
element `A[0, 2]`, and `A[[0, 2]] = 5` writes only that element.** [repro]
- Where:
  - `matrix_indexing.hpp:186`. `parse_matrix_subscript` treats a `list` like a `tuple`. NumPy
    (since 1.23) treats a list as an index array on axis 0, never as a tuple.
  - Related silent cases in `slice_from_object`:
    - `py::isinstance<py::int_>` accepts `bool` (99), so `A[True, 0]` is `A[1, 0]`.
    - Index arrays are force-cast to `long long` (150), so float index arrays are truncated.
- Repro (`t1.py`, `t30.py`), a = arange(12).reshape(3, 4):
  ```
  A[[0, 2]]                 pc 2.0                 np rows 0 and 2 (2 x 4)
  A[[0, 2]] = 5 on zeros    pc sets (0, 2) only    np sets rows 0 and 2
  C[[0, 3]] (causal)        pc True                np rows 0 and 3
  A[True, 0]                pc 4.0 (= A[1, 0])     np [[0, 1, 2, 3]]
  A[np.array([0.7, 1.9]), 0] pc [0, 4]             np IndexError (arrays used as indices must be integer)
  A[[1]]                    pc TypeError           np row 1

- Scenario: `M[[i, j]]` ("rows i and j") is a common NumPy idiom. With a two-element list it

- Fix:
  - Only a `tuple` is a multi-axis key. A list (or ndarray) on its own is an index array on axis
    0, with the column axis a full slice.
  - Reject `bool` / `np.bool_` scalars as indices, or implement NumPy's 0-d boolean rule.
  - Accept only integer or bool index arrays (`arr.dtype.kind in "iub"`), else raise

- Regression test: an indexing table against NumPy covering list keys of length 1 and 2, bool
  scalars and float arrays, for `__getitem__` and `__setitem__`, dense and causal.
- **Fixed (session 9):** only a tuple is a multi-axis key; a list, array or slice key indexes
  rows with every column; bool scalars and non-integer index arrays raise `IndexError`; `[]` is
  an empty integer index. `A[i]` alone still raises (C-13). `test_3_7_C2_list_keys_index_rows_as_numpy`.

- Where:

    fall through to "Unsupported dtype".
  - `from_array` (`matrix_api.py:111`) calls `np.ascontiguousarray`. That fixes the strides of
    `pc.matrix` but not the byte order. `pc.asarray` (the native function, public), `A + arr`,
    `A @ arr`, `arr @ A`, `A - arr` and vector operands do no normalisation.
- Repro (`t6.py`), values 1..6 as 2 x 3:
  ```
  '>f2' (big-endian float16)  pc.matrix / pc.asarray / Z + arr / I @ arr -> [3.58e-06 3.81e-06 ...]
  struct field (stride 9)     pc.asarray / Z + arr / I @ arr -> [1.0, 0.0, 3.16e-322, ...]   (pc.matrix OK)
  1-D struct field            pc.asarray -> [1.0, 0.0, 3.16e-322]

- Scenario:
  - FITS and many HDF5 / instrument files are big-endian. Physics users read them with

  - Record arrays and pandas `to_records()` give field views with odd strides.
  - The float16 and stride cases give wrong numbers with no error.

    In Python terms: `np.require(arr, arr.dtype.newbyteorder("="), "A")`.
  - Copy (`np.ascontiguousarray`) when a stride is not a multiple of the item size.
  - Decide object / longdouble explicitly: `TypeError` naming the dtype, or convert object
    arrays by `np.result_type`.
  - Then one templated copy (C-12).
- Regression test: import every dtype as native, swapped, F-ordered, negative-stride, stride-0
  and struct-field arrays through `pc.matrix`, `pc.asarray`, `A + arr` and `A @ arr`, compared
  with NumPy.
- **Fixed (session 9):** `normalize_numpy` (numpy_import.hpp) at the top of every importer
  (`asarray`, `vector_from_numpy`, `matrix_from_numpy`, the element-wise operand import): native

**C-16 (S4 nit, robustness) Static Python objects and the global translator.** [citation]
- `scalar_args.hpp:122`: `static py::object np_generic` is destroyed at exit after
  finalisation; `bindings_common.hpp` deliberately leaks its statics for exactly this reason.

  one copy per translation unit.
- `dtype_arg` (`bindings_common.hpp:149-150`) imports inside a C++ static-init guard. The first
  concurrent use from two threads can deadlock (thread A holds the guard and waits for the GIL

## Proposed changes (priority order)
1. Closed objects: one storage guard in `export_numpy` and in `PersistentObject`. `ValueError`,
   never a crash (C-1).
2. Indexing keys: a list or array alone is an axis-0 index array; reject bool scalars and
   non-integer index arrays (C-2). Same parser for `__setitem__`.
3. One NumPy importer: normalise byte order, alignment and strides, then one templated copy.
   Delete the five ladders and the extra dtype tables (C-3, C-12).
4. Pin storage before every GIL release; `PersistentObject::shared_mapper()` by value. Then
   3.4 C-5's GIL release becomes safe (C-4).
5. One assignment normaliser: NumPy shapes with dropped axes, array-likes and pycauset operands,
   `py_to_element` semantics, validate before writing (C-5).
6. Exceptions: no `cast_error` / `RuntimeError` for user errors. Delete
   `translate_invalid_argument`. `IndexError` / `MemoryError` / `ValueError` where NumPy uses
   them. Update Warnings & Exceptions.md and to_numpy.md (C-6, C-18).
7. One element read / write helper for matrices and vectors on ViewValue's rules, integer
   factors included (C-7).
8. Remove the view-flag setters from the public API; a validating private restore for
   persistence (C-8).
9. One operand normaliser for matrix / vector arithmetic, matmul and bitwise. 0-d arrays are
   scalars; Python ints are range-checked by `scalar_op`. The under-promotion warning is
   emitted there (C-9, C-10).
10. Fold views on write with `write_out` (blocked, file-backed when large) (C-11).
11. Indexing coverage: single-axis keys, vector slices / fancy, 2-D masks, structured windows
    via the typed reader (C-13).
12. Public surface: `_asarray` + a facade `pc.asarray`; underscore `set_storage_root`; drop
    `MatrixBase.eig*` / `matmul`, the dead `norm` and `dynamic_attr`; register classes before
    methods so signatures are Python names; an API-surface test that fails on additions (C-14).
13. Clean-up: C-15 to C-17.
14. Tests: indexing and assignment tables against NumPy, an import grid (byte order / strides),
    an exception-class table, the two-thread close race in a subprocess, an RSS bound for view
    writes.
