## What it does
`__init__.py` is the public module. At import it (1) sets `OMP_WAIT_POLICY` /
`OPENBLAS_THREAD_TIMEOUT` and warns if NumPy was imported first (19-70), (2) defines the dtype
tokens as plain strings (76-98), (3) loads the extension through `native.import_native_extension`
(162-163) and sets OpenBLAS threads through ctypes (`native_setup`, 166-168), (4) imports the
physics layer eagerly (175-177), (5) creates `./.pycauset` in the cwd and sweeps it for `*.tmp`
(`runtime`, `_storage`, 218, 295-300), and (6) monkey-patches the native classes: `__array__`
(export guard), `__array_ufunc__ = None`, a Python `__setitem__` (307-382), `save`, `conjugate`
(529-531), `__str__` / `__repr__` (`matrix_api.register_native_matrices`, 537) and a debug-timing
`__matmul__` on every matrix class (543-561). The rest are public functions: constructors
(`vector`, `matrix`, `zeros/ones/empty`, `causal_matrix`, `identity`, `symmetric`,
`antisymmetric`, `hermitian`, `diagonal`), file helpers (`save/load`, `*_npy/npz`,
`convert_file`, `to_numpy`), configuration (`set_backing_dir`, memory threshold, export ceiling,
`debug_mode`, IO traces) and thin wrappers over `_internal/ops.py`. `__getattr__` (1237) forwards
every unknown name to the native module, and `__all__` is `dir(_native)` minus two names plus a
hand list (1246-1360). `__init__.pyi` overrides the module for type checkers.

## File-by-file notes

### python/pycauset/__init__.py
1. Purpose: the public surface, but also import-time configuration, class patching and four
   operations computed in NumPy (`symmetric`, `antisymmetric`, `hermitian` validation,
   `diagonal`). Architecture.md calls it "thin: argument checks, then the engine"; that is not
   true for those functions (C-4) nor for the names served by `__getattr__`.
2. Liveness (grep + vulture):
   - `_safe_get` (189-190) is never called; `native.safe_get` exists only for it.
   - `vector()` line 591 (`kwargs.pop("max_in_ram_bytes", ...)`) cannot fire: the parameter is
     keyword-only, so `kwargs` never holds it.
   - The concrete-class loop (377-382) does nothing: the `__pycauset_*_wrapped__` flags are
     inherited from the base classes, so every subclass is skipped [repro, p4.py], and no
     subclass overrides `__setitem__` / `__array__` anyway.
   - `__array_priority__` (323) has no effect once `__array_ufunc__ = None`.
   - `_storage_root()` (226) is used only by tests.
   - `import sys as _sys` twice (19, 110); `set_backing_dir` re-imports `warnings` and the
     warning class locally (241-243).
3. Correctness: `str()` of scaled views (C-2); silent dtype / kwargs drops (C-3); NumPy
   computing behind `divide`, `bitwise_*`, structured constructors (C-4); `invert` naming (C-7);
   star import (C-8); constructor edge cases (C-20); `save_npy` & co. return paths that do not
   exist (C-15).
4. Out-of-core: `diagonal(1-D)` builds an n x n NumPy array; `symmetric(...)` of a PyCauset
   matrix exports it whole (C-4). `load_npy` now memory-maps (3.9 C-12 fixed).

9. Docs: see C-23.
10. Tests: `test_api_surface.py` covers the constructors on happy paths. Nothing covers `str()`
    of a view, invalid `dtype=` on vectors, kwargs on vector/zeros, star import, thread use of

## Findings

**C-1 (S1 critical, user data loss) The storage sweep deletes every `*.tmp` and `*.raw_tmp` file
under the backing directory, recursively, whoever created it.** [repro]
- Where: `_storage.py:19-24,51-64` (`os.walk` + suffix test only), called by
  `runtime.set_storage_root` (`runtime.py:41`), `initial_cleanup` at import
  (`__init__.py:295`) and the atexit sweep of every root used (`runtime.py:56-75`).
- Repro (inline):
  ```
  userdir/project/notes.tmp, userdir/project/build/obj_1234_5.tmp, userdir/project/data.csv
  pc.set_backing_dir("userdir")
  -> only userdir/project/data.csv is left
  ```
- Scenario: `pc.set_backing_dir("/scratch/me")`, `"~"`, `"/tmp"`, a project directory or a
  shared disk. Editor swap files, other programs' temp files, a crashed download named `*.tmp`
  anywhere below are deleted at that call, at every later import whose cwd root is that directory,
  and at exit. The pid guard protects only names of the form `_<pid>_<n>.tmp` of live processes.
  The docs promise "files of earlier runs that crashed" (Storage and Memory.md:98-101). 3.9
  noted the recursive walk for staging files; the user-file loss is the worse consequence.
- Fix: delete only files PyCauset can prove it made: the exact name pattern
  `^<known prefix>_<pid>_<n>\.tmp$` of `StorageUtils.cpp` (prefixes from one shared table), only
  directly in the root (no recursion), and only if the pid is dead. `.raw_tmp` staging files live
  next to save targets now, so drop them from the sweep. Better still (3.1 proposal): unlink temp
  files right after creating them (POSIX) so no sweep is needed.
- Regression test: a root containing `notes.tmp`, `sub/x_1_2.tmp`, `a.raw_tmp`; after
  `set_backing_dir`, import in a subprocess, and interpreter exit, all three still exist; a
  `dense_float_<deadpid>_0.tmp` is removed.
- **Fixed (session 9):** the engine names temp files `<prefix>_<pid>_<n>.pycauset-tmp`
  (StorageUtils.cpp; `PersistentObject` marks only that suffix temporary), and the sweep
  deletes only that exact form, directly in the root (`_storage.py`).
  `test_3_8_C1_the_sweep_leaves_other_files_alone`.

complex number.** [repro, p4.py]
- Where: `formatting.py:44-57` multiplies `matrix.get(i, j)` by `matrix.scalar`; `get` already
  applies the view (`(A*2).get(0, 1)` is 4.0 for A[0,1] = 2). `scalar` is complex for every

**C-5 (S2 major, thread safety / global state) Per-call placement (`storage="disk"`,
`max_in_ram_bytes`) is done by changing the process-global memory threshold.** [repro, p6.py]
- Where: `native_threshold.py:7-27`, used by `matrix_api.py:113-120` and `factories.py:36-41`.
- Repro:
  ```
  two overrides interleaved (A enters, B enters, A exits, B exits) -> threshold stays 0 for the rest of the process
  thread 1: 3000 x pc.matrix(64x64, storage="disk"); thread 2: 20000 x pc.zeros((8,8))
      -> 92 of thread 2's 8x8 matrices were file-backed; threshold restored at the end only by luck
  ```
- Scenario: a thread pool or a Jupyter background task importing data with `storage="disk"`
  while the main thread computes: unrelated small matrices go to disk (orders of magnitude
  slower), or the threshold ends at 0 permanently and every later allocation is a file.
- Fix: pass placement as an argument (`native.asarray(arr, placement="file"|"auto",
  max_ram_bytes=...)`) and decide it in `initialize_storage` for that object only. Delete
  `native_threshold.py`.
- Regression test: the interleaving above leaves `get_memory_threshold()` unchanged; the
